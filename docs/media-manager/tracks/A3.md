# Track A3 (M3): folders

Follow [M3-wave-A.md](M3-wave-A.md) and [README.md](README.md).

**You own:** `features/folders/**` and the per-track files named in M3-wave-A.md.

**Starting point:** the shell already gives the folder column its resizer, collapse, `inert` and drawer
below 900 px. The `FolderColumn` stub is yours to build. Spike C3 (`docs/media-manager/tracks/spikes/C3.md`
and F3's `test/spikes/c3/`) has a working virtual tree, the Pragmatic hitbox (nest vs reorder), a live
preview, auto-expand and auto-scroll. Lift it, as C3.md recommends.

**Deliverables** ([specs/folders.md](../design/specs/folders.md) in full, interaction-spec §6–§7):

1. **The column:**
   - All files, Uncategorized, then the nested tree;
   - direct or nested counts (a per-user preference, stored locally);
   - expand/collapse all;
   - folder search that keeps ancestors visible;
   - the header with New folder (`N`) and the options menu;
   - Trash row integration point for B3 (render a slot or a stub row when `bootstrap` says trash is on).
2. **The tree:**
   - an ARIA tree with a roving tabindex, virtualised;
   - arrows, Home/End, Enter/Space to open a folder (which sets `?folder=`, replace per D16, and clears
     the selection);
   - Delete, `N`, `R`, `M` and ContextMenu on the focused row.
3. **Create and rename inline:** duplicate names become "Name (1)", explained in a toast. Rename has an
   Undo toast.
4. **Delete:** a confirm that explains the subtree, and that files move to Uncategorized. No Undo.
5. **Context menu:** right-click or the ContextMenu key.
6. **Drag and drop:**
   - tiles or the selection onto a folder, with a pointer-following "Move N items · to X" preview,
     auto-expand after 700 ms, edge auto-scroll, and an Undo toast;
   - folders can be reparented and reordered (cycle check; refused targets explain why);
   - use `core/dnd`'s `useMediaDraggable` on tiles. The tiles are A1's, so ask A1 via a change request
     if needed, or attach it from your side through the exported drag data.
7. **Move to… (`M`):** a searchable dialog with Recent folders and "Create folder". It's the triage flow:
   moved items leave the selection and focus moves to the next item.
8. **Scenarios:**
   - FileBird Pro (D42): colours and folder sort, with colours only through the plugin, and hidden on
     Lite (D23);
   - per-user mode (D25): own folders, read-only, with a notice;
   - no FileBird: no folder UI at all;
   - Author counts (D41).
9. **The `Delete` key inside a folder means "remove from folder"** (system.md §4). Implement that
   command here; B3 implements library delete.

**Backend:** the folder routes, assign and counts all exist (server-api.md §7.8–7.11). Use them via
`core/data/folders.ts` (yours). The performance of tree search and counts at 300 folders comes from the
`large` seed.
