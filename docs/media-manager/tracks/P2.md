# Track P2 (M1): companion plugin, mutations, usage and images

Follows the rules in [README.md](README.md).

**Goal:** the plugin's write side, from [contracts/plugin-api.md](../contracts/plugin-api.md): §5.4–5.15,
the usage index (§8, including Visual Portfolio, D22), edit backups (§8.3), and the `wpu` keys P2 owns
(`WPU_FIELD_PROVIDERS` in `shared/plugin-api.ts`: `edited`, `editedAt`, `undoable`, `restorable`,
`sizesPending`, `usageCount`).

**You own:**
- `plugin/wp-upload-companion/src/Index/UsageIndex.php`;
- `src/Rest/{Media,Trash,Usage,Images}Controller.php`;
- any new directories under `src/` for images, usage parsing and backups (for example `Images/**`,
  `Usage/**`);
- `plugin/tests/contract/{media,trash,usage,images}*.spec.ts`;
- your handoff note `P2-handoff.md`.

**Not yours:** everything P1 owns ([P1.md](P1.md)), the entry file, and the versions (never bump them).
Your `wpu` keys plug into P1's provider model. Until it lands, implement your providers against the
interface P1 publishes. If you need to start before then, ask in your handoff note.

**Spikes first,** each written up in `spikes/<id>.md`:
- **X2:** in-place edit that overwrites the file and keeps the same URL (D19). Shim `wp_save_image` /
  `wp_restore_image`, or build your own `WP_Image_Editor` pipeline with backups. Settle GD vs Imagick
  and AVIF.
- **X3:** replacing a `-scaled` image. If the URL can't be kept, report `urlChanged` (D20: the UI warns,
  then proceeds).
- **X7:** usage-parser accuracy and backfill throughput under `max_execution_time`.
- **X10:** the Visual Portfolio parser (D22), using D's seed (block `images`, loop-gallery
  `imagesQuery.images`, `vp_lists` saved layouts with `vp_images`, the `visual-portfolio/saved` block and
  the `[visual_portfolio id=N]` shortcode). It runs only while Visual Portfolio is active.

**Then, in order:**
1. `POST /media/batch` (unblocks the server's batch route).
2. Trash and delete.
3. Usage (the index, backfill, and core plus Visual Portfolio contexts).
4. Image operations: edit with `expectedModified`, undo, restore, regenerate, replace.

**Also:**
- Per-item capability checks.
- 20 s time budgets, returning `remaining` ids.
- MIME and extension validation on replace.
- Prepared SQL everywhere (contract §11).
- Permission callbacks return 403 `WP_Error`s, never `false`.

**Tests:** contract tests against your `dev/run up test` stack for every route. Cover:
- Editor and Author (D26 gives you both users);
- `MEDIA_TRASH` on and off;
- Visual Portfolio on and off;
- image edits checked on real files: the dimensions after each recipe, backups present, Undo and
  Restore round-trips.
