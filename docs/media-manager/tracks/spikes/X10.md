# Spike X10: Visual Portfolio usage (D22)

**Result:** the storage the contract describes (§8.2) is confirmed against Visual Portfolio 3.11.0
itself, and the parser reads all of it. The context is scanned only while Visual Portfolio is active.

## Method

Visual Portfolio 3.11.0 installed by hand (`dev/run wp plugin install visual-portfolio --version=3.11.0`).
For each storage form, a post or layout was written with known attachment ids, then **rendered by
Visual Portfolio** (`the_content` / its shortcode). The ids it rendered are exactly the ids the parser
reads, so the parser reads what Visual Portfolio reads.

| Form | Where the ids are | Visual Portfolio rendered | Parser |
|---|---|---|---|
| `visual-portfolio/block` | `attrs.images[].id` | 4, 6 | 4, 6 |
| Gallery Loop `visual-portfolio/loop` | `attrs.imagesQuery.images[].id` | 7, 8 | 7, 8 |
| Legacy saved layout (`vp_lists`, no blocks) | meta `vp_images[].id` | 10, 11 | 10, 11 (on the layout) |
| Block-based saved layout (`vp_lists` with a loop) | its content's loop `imagesQuery.images` | 12 | 12 (on the layout) |
| `visual-portfolio/saved {"id":"<layout>"}` | the layout's images | 10, 11 | 10, 11 (on the post) |
| `[visual_portfolio id="<layout>"]`, also unquoted | the layout's images | 12 / 10, 11 | same (on the post) |
| Loop synced to a layout (`savedLayout.id`) | the loop's **own** `imagesQuery` (the layout only lends its template) | — | not a use of the layout's images |

Image entries without an id (an external `imgUrl`) are skipped, as are ids that are no attachment. The
legacy block name `nk/visual-portfolio` (old saved-layout block, `attrs.id`) is read like
`visual-portfolio/saved`. Track D's seed (`mm/d-m1`) builds its galleries with Visual Portfolio's own
`Visual_Portfolio_Loop_Gallery::create()`, which writes the same storage.

## Switching Visual Portfolio on and off

- **Off:** at `init`, the index sees the change and deletes every `visual-portfolio` row; `rev` moves.
- **On:** posts that can hold galleries (`vp_lists`, or content containing `visual-portfolio` /
  `[visual_portfolio`) are marked for a rescan and the index goes `building` until the maintenance step
  has rescanned them. Saving a layout rescans the posts that embed it (50 at once, the rest via
  maintenance). Covered by `usage.spec.ts` ("drops and restores the context…").

## Decisions and caveats

- `content_source` / `queryType` aren't checked: a block switched from "images" to "posts" keeps its
  old `images` attribute and still counts. That errs towards "used", which is the safe side for
  delete decisions. Open question in the handoff note.
- Editors can't create `vp_lists` over REST (Visual Portfolio requires more than `edit_posts`), so the
  contract tests check saved layouts against track D's seeded layouts when present.
- Visual Portfolio creates its own **placeholder attachment with `post_author` 0** the first time it
  renders a gallery. P1's `wpu.author` schema requires an id above 0; see the handoff note.
