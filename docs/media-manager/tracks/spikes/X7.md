# Spike X7: usage-parser accuracy and backfill throughput

**Result:** exact on the seed and on 2000 synthetic posts; about **275 posts/s** in one PHP worker, so
the default 5 s maintenance budget (contract §5.21) scans ~1400 posts per step and a 5k-post site
needs 4 steps. No change to the step budget or to the "index incomplete" wording is needed. Parser:
`plugin/wp-upload-companion/src/Usage/Parser.php`; index: `src/Index/UsageIndex.php`.

## Accuracy

**Seed (`dev/run seed small`, 30 posts):** every context matches what the seed script wrote.

| Context | Rows | Seed ground truth |
|---|---|---|
| `image-block`, `file-block`, `cover-block`, `media-text` | 10 each | 10 posts each (the seed rotates five block kinds over 25 posts) |
| `gallery-block` | 44 | 9 nested galleries + 1 legacy `ids` gallery, 3–6 images each |
| `featured` | 23 rows, 19 items | 3 of 4 posts; the "hero" image is shared |
| `content` | 5 | 5 classic posts with `wp-image-N` (their URLs resolve to the same ids, no double count) |
| `shortcode-gallery` | 12 | 3 `[gallery ids]` × 4 |
| `video-block`, `audio-block`, `site-logo`, `site-icon` | 1 each | 1 each |

Images inside media blocks never count again as `content`: the parser reads those blocks from their
attributes and skips their own markup (`innerHTML` excludes inner blocks, which are walked separately).

**Synthetic (2000 posts, ~3 KB of blocks each, six uses per post):** `image-block`, `gallery-block`,
`content` (a link to a *sub-size* URL) and `featured` 2000 rows each, `shortcode-gallery` 4000 —
exactly as generated.

URL resolution: every upload URL in the markup is matched **by path** (whatever the host, so a site
moved between hosts keeps its usage), and resolved in one `IN (…)` query per post against
`_wp_attached_file` with these candidates: the path, the path without `-<w>x<h>` (sub-sizes), with
`-scaled` / `-rotated` (unscaled originals), and `<name>.pdf` for `<name>-pdf.jpg` previews.

## Throughput

Backfill driven over HTTP through P1's `POST /maintenance/step` (`budgetMs: 5000`), from an emptied
index, 2036 indexable posts:

| Step | Posts scanned | Index |
|---|---|---|
| 1 | 1380 | building 1380/2036 |
| 2 | 657 | ready 2036/2036 |

Batches of 50 by ascending id; the deadline is checked before every post, so a step overshoots its
budget by at most one post. `status()` reads only the state option (P1's `/rev` stays cheap); steps
recount `done`/`total`, and hooks adjust `total` when sources appear or go.

## Not detected (by design or for later)

- Page builders, ACF, WooCommerce, theme files, custom CSS (D22; the UI says the index may be incomplete).
- `[gallery]` **without** `ids`/`include` (it shows the post's attached images): not counted.
- Links to attachment pages (`?attachment_id=N`, permalinks of attachments).
- A synced pattern (`wp_block`) counts as the user; the posts that embed the pattern don't.
- Posts in the Trash, auto-drafts and revisions are not indexable (contract §8.2).
