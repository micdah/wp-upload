# Spike X3: replacing a `-scaled` image (D20)

**Result:** the attached file's URL can **always** be kept. `POST /media/{id}/replace` reports
`urlChanged: false` in every case measured; `urlChanged` stays in the contract as the escape hatch, and
the UI warning of D20 isn't needed for replace. Implemented in `Images\Engine::replace_image()`.

## The problem

Core's `wp_create_image_subsizes()` decides from the *new* file whether to make a `-scaled` copy, and
names files after the upload. Calling it with the replacement would change the attached name whenever
the new image is on the other side of the 2560 px threshold (`big_image_size_threshold`), or rotated
by EXIF (`-rotated`).

## What the plugin does instead

The attached file name never changes; only what is stored under it does.

| Item | Replacement | Attached file (same name) | `original_image` |
|---|---|---|---|
| `photo-scaled.jpg` | over the threshold (or EXIF-rotated) | the scaled/rotated version | the upload, under the existing original name `photo.jpg` |
| `photo-scaled.jpg` | under the threshold | the upload itself | removed, and the old `photo.jpg` deleted: the item is no longer a scaled copy |
| `photo.jpg` | over the threshold (or EXIF-rotated) | the scaled/rotated version | the upload, as `photo-original.jpg` |
| `photo.jpg` | under the threshold | the upload itself | none |

Then every registered sub-size is rebuilt from the attached file under `<stem>-<w>x<h>.<ext>` (the
stem the old sizes used), files the old sizes used and the new ones don't are deleted, the undo stack
and the original this plugin recorded are dropped, and `post_modified` is updated.

## Measured (dev stack)

| Case | Before | After | URL |
|---|---|---|---|
| Seeded `misty-market-038-scaled.jpg` → 1536×1152 JPEG | 2560×1920 (original 3200×2400) | 1536×1152, no original | same |
| Same item → 2400×3600 JPEG | 1536×1152 | 1707×2560, original 2400×3600 | same |
| `calm-lantern-075.jpg` (800×1600) → 2400×3600 JPEG | no original | 1707×2560, `calm-lantern-075-original.jpg` | same |
| PNG onto a JPEG item | — | 415 `wpu_mime_mismatch` (`expected: image/jpeg`) | — |

Contract tests: `images.spec.ts` → `replace` (same URL, bytes, dimensions, `original_image`).

## Side effects to know

- Sub-size URLs whose **dimensions change** (a new aspect ratio) stop existing; posts that embedded
  that specific sub-size show a broken image. Same as uploading anew; listed as an open question.
- Images edited in **wp-admin** keep wp-admin's backups after a replace, so "Restore original" can still
  bring back the pre-replace original (through core, `urlChanged: true`).
- The upload goes through `wp_handle_sideload()` and `wp_check_filetype_and_ext()` with the user's
  allowed types (contract §11); the dev stack's PHP limit is 2 MB (`upload.maxBytes`).
