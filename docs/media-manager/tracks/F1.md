# Track F1 (M1): client core runtime and shell

Follows the rules in [README.md](README.md).

**Goal:** the client foundation every feature track builds on: plan §3–§4 (foundation APIs) and
interaction-spec §1, §6, §8 and §10. You continue as the M2 vertical-slice agent afterwards. At the M2
gate, `core/`, `app/` and `shell/` pass to the orchestrator.

**You own:**
- in `client/src/media-manager/`: `app/**`, `shell/**`,
  `core/{state,url,collection,commands,keymap,perms,ui,dnd,uploads}/**`;
- `client/src/App.tsx`;
- your handoff note `F1-handoff.md`.

**Not yours:**
- `core/data/**` and `mocks/**` (F2);
- `theme/**`, the client test config and `client/vitest.config.ts` (F3);
- `features/**`: keep the stub exports' names;
- `client/src/legacy/**`, `main.tsx` and `vite.config.ts`.

**Deliverables:**
1. **The core store** (Zustand): selection plus anchor, focus, overlay, zoom, panels (persisted),
   connectivity, bootstrap. Feature-local stores stay in features.
2. **`useUrlState`:** query params as in interaction-spec §1, plus `view` until M5. Entering detail
   pushes a history entry. Stepping, filter changes and **folder changes replace it (D16)**. Leaving
   detail calls `history.back()` when we pushed.
3. **Commands:** a `CommandMap` (declared up front, extended by module augmentation), `implementCommand`,
   `runCommand` and `useCommand`. Unimplemented commands render disabled.
4. **The keymap:**
   - `registerBindings` asserts the US + DK layout rule over every binding, and checks for conflicts;
   - one dispatcher, plus `useKeyLayer` for Esc layering;
   - suspended in text fields, modals, menus and listboxes.
5. **UI helpers and permissions:**
   - `toast()`/`undoLast()` (Mantine notifications behind our own API), `announce()` (one polite live
     region), and `confirm()` with rich content and type-to-confirm;
   - `can()`/`partition()`, fed by bootstrap, `wpu.perms`, connectivity, FileBird mode, Pro, and plugin
     `features[]`.
6. **Shared hooks:** `useCollection`/`useItem`/`useTargets`, `centerApi`, `useMediaDraggable`
   (Pragmatic DnD) and the tile upload-state type.
7. **The shell:**
   - layout with a toolbar slot, the folder column (resizable, collapsible, `inert`), centre stack,
     inspector rail and panel, overlay slots, and breakpoints;
   - boot: plugin check first → Onboarding stub or Shell;
   - **login, session-expired, "WordPress unreachable" and logout UI in the new theme**, with the auth
     state machine extracted from `legacy/UploaderApp.tsx` into a shared hook. Leave `legacy/` itself
     untouched: copy, don't move.
8. **Spikes:**
   - **C2:** the morph with a virtualised grid, including returning to a far-away tile, in Chrome,
     Firefox and Safari engines via Playwright;
   - **C4:** Esc and key layering against Mantine Menu, Modal and Combobox.

**Inputs:** F2's data layer and mocks land in parallel. Until then, code against the types in `shared/`
and use the fixtures directly in tests. F3's theme lands in parallel too; use Mantine defaults until it
does.

**Tests:**
- Vitest for the pure modules: the URL codec and history policy, selection, the keymap matrix (US/DK
  events, AltGr rejection, suspension), `can()`, the undo registry.
- Component tests in Vitest browser mode once F3's config lands.
