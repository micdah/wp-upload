# Track F3 (M1): theme and client quality infrastructure

Follows the rules in [README.md](README.md).

**Goal:**
- the media manager's Mantine theme from the design tokens, in both colour schemes;
- the client test harness;
- bundle and URL guards.

Plan §3–§4, §8–§9; design-system §8.

**You own:**
- `client/src/media-manager/theme/**` and `client/src/media-manager/test/**` (test utilities and spikes:
  `renderWithProviders`, US/DK keyboard helpers, the MSW test server hook-up);
- `client/vitest.config.ts`;
- `client/scripts/bundle-budget.mjs`;
- the URL-guard extensions in `server/src/app.spec.ts`;
- your handoff note `F3-handoff.md`.

**Deliverables:**
1. **The theme** from `docs/media-manager/design/prototype/css/tokens.css` and design-system §8:
   - `colors.dark` and `colors.gray`, a `neon` palette, and `primaryShade`;
   - a `cssVariablesResolver` exposing the semantic tokens (`--surface-*` and the rest) for both
     schemes;
   - radius, spacing and typography;
   - self-hosted Geist and Geist Mono via `@fontsource-variable`, imported only inside the
     media-manager chunk.

   Export a `MediaManagerThemeProvider` (theme, resolver, colour-scheme manager with its own storage
   key). F1 wires it into `app/`.
2. **`client/vitest.config.ts`:**
   - a `unit` project (node) for pure modules;
   - a `browser` project (Vitest browser mode, Playwright Chromium; in the runner the browsers come from
     the image);
   - MSW in both;
   - `passWithNoTests`.

   `client/package.json` already has `"test": "vitest run --passWithNoTests"`. If the projects need
   different scripts, request them in a change request.
3. **Guards:**
   - `bundle-budget.mjs` enforces plan §9: the initial media-manager chunk is 150 kB gzip or less, the
     media-manager code is not in the entry chunk, and the entry chunk doesn't grow by more than 5 kB
     gzip.
   - Extend `app.spec.ts` to also flag `/wp-json`, `"/assets/` and CSS `url(/`, to assert no MSW or
     `mockServiceWorker` in the dist, and to require more than one JS chunk.
4. **Spikes:**
   - **C1:** the justified layout plus TanStack Virtual at 50k. Port `prototype/js/grid.js`'s algorithm as
     a pure module in `client/src/media-manager/test/spikes/`, which you own. Measure layout time, long
     tasks while scrolling, focus pinning and resize anchoring.
   - **C3:** a virtual tree with Pragmatic DnD hitbox (nest vs reorder), a live preview, auto-expand and
     auto-scroll.

   Write each spike up in `spikes/<id>.md`. Spike code that should survive goes into a proposal in your
   handoff note. The owning feature track (A1 grid, A3 folders) builds the real thing.

**Tests:** the theme renders both schemes without contrast regressions against `token-report.mjs`'s
pairs, and the harness runs one example test per project.
