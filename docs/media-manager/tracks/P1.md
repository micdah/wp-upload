# Track P1 (M1): companion plugin, read side and structure

Follows the rules in [README.md](README.md).

**Goal:** the plugin's structure and read side, from
[contracts/plugin-api.md](../contracts/plugin-api.md): §1–3, §5.1–5.3, §5.16–5.21, §6, §7, §8 (the
media index), §9 and §10.

**You own:**
- `plugin/wp-upload-companion/src/` except the P2 files listed in [P2.md](P2.md). That is `Plugin.php`,
  `FileBird/**`, `Index/MediaIndex.php`, `Query/**`, `Field/**`,
  `Rest/{Info,Collection,Folders,Maintenance}Controller.php`, and any new directories for these concerns.
- `plugin/scripts/build.mjs`, `plugin/vitest.config.ts`, `plugin/composer.json` and
  `plugin/composer.lock` (PHPStan with WordPress stubs, dev-only).
- `plugin/tests/contract/{support/**,info,rev,collection,facets,field,folders,maintenance}*.spec.ts`.
- Your handoff note `P1-handoff.md`.

**Not yours:**
- The entry file `wp-upload-companion.php` and the version constants. **Never bump versions**; the
  orchestrator does it at merge time.
- `plugin/scripts/check-version-bump.mjs` and `plugin/CHANGELOG.md`. Propose changelog lines in your
  handoff note.

**First deliverables** (these unblock S1 and the M2 slice):
1. `GET /info` with its frozen shape, including the 403 that still identifies the plugin.
2. `GET /rev`, with the atomic `wpu_rev` bump and the hooks that bump it.
3. `GET /collection`, with all params.
4. The `wpu` field, including the provider model P2 plugs into. Publish that interface early: P2 needs
   it.
5. `GET /folders`.

**Then:** `GET /facets`, the folder mutations (`POST`/`PATCH`/`DELETE /folders`, `/folders/assign`) and
`POST /maintenance/step`, plus `MediaIndex` (schema via a db-version option, hooks, backfill,
stale detection).

**Also:**
- **Permission callbacks** must return a `WP_Error` with status 403, never `false`. Core turns `false`
  into 401 for anonymous calls, which the contract forbids (§1).
- **FileBird:** read with read-only SQL; mutate only through FileBird's own PHP functions (D17). In
  per-user mode, show the user's own folders read-only (D25). Colours are Pro-only (D23).
- **`build.mjs`:** produce `plugin/dist/wp-upload-companion/wp-upload-companion.php` (a single file with
  bracketed namespaces and no autoloader), the zip, and the `plugin.json` and `changelog.json` sidecars
  (D30). The built file must work as a regular plugin and as a mu-plugin.
- **Spikes:**
  - **X9 (Pro detection):** no licence (D15). If detection can't be made reliable, `pro` is always
    false in v1.
  - **X4 (performance at 50k):** with D, once D's `large` seed exists. Measure against plan §9, and
    write the result to `spikes/X4.md`.

**Tests:** contract tests over HTTP against your `dev/run up test` stack (with the built plugin), for
every route above, on Editor and Author, and with FileBird off and in per-user mode. Each response is
validated with the zod schemas in `shared/` (`plugin-api.ts` types). `dev/run test plugin-static` and
`plugin-contract` must pass.
