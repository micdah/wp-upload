# Track S1 (M1): server, read side and plugin client

Follows the rules in [README.md](README.md).

**Goal:** the Express side of [contracts/server-api.md](../contracts/server-api.md) for reading, plus the
shared server plumbing S2 builds on. Covers §1–6, and §7 for bootstrap, rev, collection, facets, items
(GET and `PATCH /items/:id`) and folders.

**You own:**
- `server/src/routes/library/{index,bootstrap,rev,collection,facets,items,folders}.ts`;
- `server/src/lib/library/{pluginClient,cache,errors}.ts`;
- `server/src/lib/library/normalise/{items,folders}.ts`;
- their specs;
- `server/vitest.live.config.ts` and `server/src/**/*.live.spec.ts` for your routes;
- your handoff note `S1-handoff.md`.

**Not yours:**
- `app.ts` (it already mounts `libraryRouter` at `/api/library`);
- `routes/library/notImplemented.ts` (delete it only when the last stub goes, and say so);
- S2's routers;
- the legacy routes and libs.

**First deliverable** (S2 starts from it, so commit it early and say so in your handoff note):
`pluginClient.ts` and `errors.ts` with their final signatures:
- a WordPress and plugin client on `wpAxios`, with per-call timeouts (list calls short; never the 5-min
  upload timeout);
- `toLibraryError()`, with the mapping table and its precedence rule (server-api §2).

**Then:**
1. `bootstrap`, with every `wp.state`/`plugin.state`, `plugin.bundled`, and the compatibility check
   from plan §2.6.
2. `rev`.
3. `collection`, `facets`, `items?ids=&view=tile|full` (hydration via `include=` with `_fields` and the
   `wpu` field; spike X5), and `PATCH items/:id`.
4. The folders routes.
5. Caching: an LRU keyed by `rev`, single-flight, `ETag`/304, and `X-Library-Rev` (§3).
6. Compression, scoped to `libraryRouter` in `routes/library/index.ts`.

**Tests:**
- Unit and route specs as in the existing server tests (`vi.spyOn(wpAxios)`, supertest), using the
  fixtures in `shared/fixtures/`.
- Live specs (`*.live.spec.ts`, excluded from the default config) against your `dev/run up test` stack.
  They become useful as P1's routes land; until then, test against core routes and stub the plugin.
- `dev/run test unit` and `server-live` must pass. `npm run test -w server` must still pass without a
  WordPress, because `ci.yml` runs it.
